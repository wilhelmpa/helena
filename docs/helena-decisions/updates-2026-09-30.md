# Update validation

The Update Center reports completion only after the installed target passes its smoke
test. Runtime failure restores the previous version and tests it again. A rollback
failure remains a failed action and names the required recovery.

## Runtime configuration

`/etc/helena/update.json` needs a `runtimeSmoke` entry for each family (`codex`,
`claude`), with `user`, `home`, `profile`, and `model`. Use an existing service account
and its existing authenticated profile. Codex uses `CODEX_HOME`; Claude uses
`CLAUDE_CONFIG_DIR`. The helper checks these paths without reading credentials and
never creates a login. The Codex test model is `gpt-6.1-sol`; the Claude entry must
use the model assigned to Ava. Missing configuration disables the corresponding
update action with its reason.

CLI smoke executes a short prompt and checks assistant output. ACP smoke performs
initialize, session creation, model selection and a completed prompt; Codex also
requires read-only mode. Version output cannot satisfy this check.

The Hermes helper also requires a `modelSmoke` argument list in its root
configuration. That command must invoke the installed Hermes runtime with its
existing service profile and return only `VOLITION_UPDATE_OK` from a real model
response. The helper runs it after activation and again after rollback; without
this configuration Hermes updates remain disabled.

## Codex ACP 2.0.1

The installed 1.13.1 package depends on Codex `^0.156.1`. Its native optional
platform package is absent because the installer omitted optional dependencies.
The installer includes those dependencies and verifies that the adapter's bundled
Codex starts before switching. No package pin is advanced during deployment.

[2.0.1](https://github.com/agentclientprotocol/codex-acp/releases/tag/v2.0.1)
updates Codex to `^0.159.1`; 2.0 changes the AIR tool contract and restores read-only
access. The smoke tests exercise ACP model IDs with reasoning suffixes and reject
failed turns, missing output, tool requests and timeouts. Full compatibility still
requires the installed 2.0.1 adapter and Ava's actual profile.

The installed Hermes source uses Codex app-server directly. The old adapter alone
does not establish the cause of Ava's model rejection. After deployment compare a
fresh Ava turn using `gpt-6.1-sol` with the adapter smoke, and retain the actual
runtime/model/error in the evidence. The requested model is documented by
[OpenAI](https://developers.openai.com/api/docs/models/gpt-6.1-sol).

## Local AI and system packages

Whisper preparation targets the existing CPU backend, its 14306 service port and
the pinned 1.9.4 source. It requires a built package, the German speech comparison
and an authorized maintenance window. These prerequisites are not installed by a
code deployment. Candidate, active and rollback speech checks remain mandatory.
The bridge reports the missing prerequisite to the Update Center.

Embedding remains a notice until an update package provides the Vulkan build,
service switch, health check, vector dimension and semantic comparison against the
same Qwen3 embedding model, and a tested rollback. A release tag does not provide
that package. Halogen is also a notice.

APT requires cached original packages and refuses dependency additions, removals
or changes outside the requested set. It checks installed versions, dpkg audit and
running product services; failures restore the cached originals and repeat the
smoke. Builds refuse an already running full gate or excessive memory pressure and
run with MemoryHigh=5G, MemoryMax=8G, CPUWeight=20. Claude must keep the gate and
update build windows separate.

## Release acceptance

Claude deploys the branch and associates the service profiles before creating
`~/agent-work/release/updates-go`. Then use the existing owner browser session and
`hl.mjs` eval-fetch with `credentials: 'include'` to check the Update Center and
apply each applicable item sequentially. Record its action and model/service smoke
proof. Verify owner and project terminals, fresh Ava Codex and Claude turns, STT
and embedding after the final action. Do not record live acceptance before these
checks finish.
